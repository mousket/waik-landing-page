## What This Phase Builds

Phase 11c shipped a **beautiful sign-off preview** (clinical summary, WAiK recommendations, verbatim narrative, signature). On submit, Mongo already stores the **verbatim narrative**, **structured clinical record**, **signature image (PNG base64)**, and **Q&A** — but:

1. **Preview insights are lost** — expert nurse summary + nurse/admin recommendations live only in Redis until submit.
2. **Signed view ≠ sign-off UI** — `/staff/incidents/[id]/report` is a simpler print layout without insights or clinical styling.
3. **PDF omits insights** — `Phase1PdfTemplate` has narrative, sections, Q&A, signature — not the new lead blocks.
4. **No email delivery** — nurses cannot send the signed record to an address they choose.
5. **Blob storage optional** — PDF works on-demand via `/api/incidents/[id]/report/pdf` without S3; email can attach generated bytes or link.

**Phase 2 handoff to DON/admin is already implemented** (`investigation-ready` in-app + push on `POST /api/report/complete`). This phase documents and verifies that path in integration QA — not a greenfield build.

## Architecture Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Persist insights | `initialReport.phase1SignoffSnapshot` on incident | Immutable record of what the nurse reviewed; survives session delete |
| Signature storage | Keep **PNG base64** in `initialReport.signature.signatureImage` | No S3 required; works with `<img>` and `@react-pdf/renderer` Image |
| SVG (optional later) | Defer | PNG is sufficient for pilot; Mongo doc size acceptable for one sig per incident |
| Signed HTML view | Reuse `ClinicalReportPreview` in **read-only** mode | One layout for preview, re-open, and print |
| PDF | Extend `Phase1PdfTemplate` with snapshot fields | Same content as signed view |
| Email | **Resend** + `@react-email` template (existing `lib/email.ts` pattern) | Matches welcome/invite emails; WAiK chrome from `emails/waik-email-chrome` |
| Email attachment | Generate PDF buffer server-side; attach **or** link to report URL if size limits hit | Resend attachment limit ~40MB; our PDFs are small |
| Who can email | Reporter + admin/DON for their facility | Server enforces `isIncidentReporter` or admin tier |
| Phase 2 notify | **No new work** — verify `investigation-ready` in task 55 | Already in `app/api/report/complete/route.ts` |

## Out of Scope (11e)

- S3 / blob storage setup (on-demand PDF remains fallback)
- SVG signature format (PNG base64 is the pilot standard)
- Email to arbitrary external parties without audit log (log `auditTrail` entry when email sent)
- Phase 2 workspace changes (see [Phase 4b](../phase_4b/phase_4b_readme.md))
